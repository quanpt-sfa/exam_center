## Cross-layer gaps to watch

- `dashboard` and `system settings` have working frontend and backend paths, but no dedicated contract doc yet.
- `master data` has broad implementation and tests, but contract coverage is fragmented across assessment- and import-focused docs.
- `delivery_submission_api.md` currently covers several distinct flows: delivery setup, proctor runtime, exam taking, and sealing. That makes change review harder.
- Worker orchestration is well tested at unit/smoke level, but the full seal -> dispatch -> capture/grading -> gradebook chain is not represented by one standalone cross-layer test or contract.
- `docs/current/api/README.md` still uses a backend start example on port `8000`, while current standalone local guidance uses `8001`.
